# 环境配置说明

本文覆盖从零到跑起来、再到部署上线所需的全部环境信息。所有变量以 [`.env.example`](../.env.example) 为准（仓库根目录），本文解释每一项的作用与取值。

---

## 一、最短路径（5 条命令）

```bash
git clone <仓库地址> && cd <仓库目录>
npm install
cp .env.example .env          # 默认 AI_PROVIDER=mock，不需要任何 API Key
npm run db:up                 # Docker 起 PostgreSQL 16 + pgvector（端口 5433）
npm run db:migrate && npm run db:seed && npm run dev
```

打开 <http://localhost:3000> 即可。种子数据包含 3 只猫、2 只狗、若干观察记录、护理知识库与 1 条待处理预警。

---

## 二、软硬件要求

| 项目 | 要求 | 说明 |
|---|---|---|
| Node.js | **≥ 20**（开发环境实测 22.22 / 20.19） | Next.js 14 的最低要求是 18.17，本项目使用了 `Array.prototype.at` 等较新 API，实际按 20 起 |
| npm | ≥ 10 | 使用 `package-lock.json` 锁定版本；不要混用 yarn/pnpm 以免锁文件冲突 |
| 内存 | ≥ 4 GB（建议 8 GB） | `next build` 峰值约 1.5 GB；视觉模型请求不占本地内存 |
| 磁盘 | ≥ 2 GB | 依赖约 570 MB，构建产物约 130 MB，上传图片随使用增长 |
| 数据库 | **PostgreSQL 16 + pgvector 扩展** | 档案与知识库向量存在同一个库里，缺 pgvector 会导致迁移失败 |
| Docker | 可选 | 只用于起数据库，应用本身直接跑在 Node 上 |
| 浏览器 | Chrome / Edge 最新版 | 星图用 Leaflet + Canvas 渲染；定位功能要求 `localhost` 或 HTTPS |

## 三、数据库：三种接法

### 方案 A · Docker（推荐，一条命令）

```bash
npm run db:up        # docker compose up -d --wait
npm run db:down      # 停止
```

`docker-compose.yml` 的实际配置：

| 项 | 值 |
|---|---|
| 镜像 | `pgvector/pgvector:pg16`（官方 PG16 + 预装 pgvector） |
| 容器名 | `straystar-db` |
| 端口 | 宿主机 **5433** → 容器 5432（避开本机已有的 5432，防止连错库） |
| 账号 / 密码 / 库名 | 均为 `straystar` |
| 数据卷 | `straystar-pgdata`（**删卷即清库**，演示前请勿执行 `docker compose down -v`） |

### 方案 B · 本机 PostgreSQL

前提：已安装 PostgreSQL 16，并装有 pgvector。

```sql
CREATE DATABASE straystar;
\c straystar
CREATE EXTENSION IF NOT EXISTS vector;   -- 必须有，否则建表时报 type "vector" does not exist
CREATE USER straystar WITH PASSWORD 'straystar';
GRANT ALL ON DATABASE straystar TO straystar;
```

然后把 `.env` 的端口从 `5433` 改成 `5432`：

```env
DATABASE_URL="postgresql://straystar:straystar@localhost:5432/straystar?schema=public"
```

### 方案 C · 远程 / 云数据库

同一连接串写到 `DATABASE_URL` 即可（需允许外网访问，并确认服务端装过 pgvector）。**注意**：远程库延迟高时，`db:seed` 的向量写入会明显变慢，属正常现象。

## 四、环境变量详解

### 4.1 数据库

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `DATABASE_URL` | **是** | 见模板 | Prisma 连接串。Prisma CLI、Next.js 运行时、seed 脚本都读这一个文件，改一处即可 |

### 4.2 认证

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `NEXTAUTH_URL` | 是 | `http://localhost:3000` | 部署到域名后必须改成外网地址，否则回调地址校验失败 |
| `NEXTAUTH_SECRET` | **是（生产）** | 占位值 | 用 `openssl rand -base64 32` 生成。**管理端 cookie 的 HMAC 也用它签名**，泄露等于伪造管理员 |

### 4.3 AI 能力

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `AI_PROVIDER` | 是 | `mock` | `mock` / `openai` / `qwen` / `glm` / `deepseek`。`mock` 是确定性规则实现，**无需任何密钥**即可跑通识别、分级、检索全流程，离线演示最稳 |
| `AI_API_KEY` | mock 下否 | 空 | 统一密钥。换厂商只改这一组变量 |
| `AI_BASE_URL` | 否 | 空 | 留空按 Provider 取官方地址；接私有部署或兼容网关时填 |
| `AI_MODEL` | 否 | 空 | 文本与视觉共用一个多模态模型时最省事（如 `glm-4.6v-flash`） |
| `AI_CHAT_MODEL` / `AI_VISION_MODEL` | 否 | 空 | 分别指定文本/视觉模型，留空回落到 `AI_MODEL` |
| `AI_EMBED_MODEL` | 否 | 空 | 向量模型。**换模型后必须重跑 `npm run ai:reembed`**，否则新旧向量不在同一空间，检索结果会全错 |
| `AI_FALLBACK_MODELS` | 否 | 空 | 文本降级链，逗号分隔。免费档高峰期返回 429/1305 时按序切换 |
| `AI_VISION_FALLBACK_MODELS` | 否 | 空 | 视觉降级链。只能降到视觉模型，降成纯文本模型等于让它闭眼看图 |
| `AI_THINKING` | 否 | 空 | `disabled` / `enabled`。开启后每次多吐一段 reasoning，实测同一句话 17 s vs 1.3 s，演示时不建议开 |
| `AI_TIMEOUT_MS` | 否 | `20000` | 整条降级链共享的总预算 |
| `AI_ATTEMPT_TIMEOUT_MS` | 否 | 空 | 单个模型的单次超时，**必须明显小于总预算**，否则主模型卡住会吃光配额，备选一次都轮不到 |
| `AGENT_TOOL_TIMEOUT_MS` | 否 | `8000` | Agent 单个工具的执行上限。接真模型后工具内部要等一次 AI 调用，建议放宽 |
| `AI_PUBLIC_BASE_URL` | 否 | `http://localhost:3000` | 把 `/uploads/xxx.jpg` 拼成绝对地址供视觉模型访问。**部署后必须改成公网地址**，否则模型拉不到图，表现为「识别不出」 |
| `OPENAI_API_KEY` / `QWEN_API_KEY` / `GLM_API_KEY` / `DEEPSEEK_API_KEY` | 否 | 空 | 厂商专用密钥，任一有值即可通过校验，优先级低于 `AI_API_KEY` |

### 4.4 存储

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `UPLOAD_DIR` | 否 | `public/uploads` | 相对路径，**换机器/换目录不用改配置**。生产环境把该目录挂到持久卷，并与数据库一起备份（只备份库会丢图） |

### 4.5 校园地理

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `CAMPUS_CENTER_LAT` / `CAMPUS_CENTER_LNG` | 否 | 见模板 | 校园中心点，**必须是 WGS-84**。抄高德/腾讯 POI 的数值（GCJ-02）会让整片星点偏 300–600 m |
| `CAMPUS_ZOOM` | 否 | `17` | 星图初始缩放级别 |
| `CAMPUS_RADIUS_M` | 否 | `2000` | 围栏半径。建档、观察落点、GPS 定位都只接受围栏内的坐标 |
| `MAP_SNAP_GRID_M` | 否 | `0` | 坐标聚合网格（米）。`0` = 不聚合；填 `50` 则把点位吸附到 50 m 网格，是隐私保守方案。全站只有 `src/lib/map/snap.ts` 一处实现 |

### 4.6 管理端

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `ADMIN_ACCOUNT` | 否 | `admin` | 未配置即为 `admin` |
| `ADMIN_PASSWORD` | 否 | 空 | 优先使用。留空回落到 `ADMIN_TOKEN`；两者都空 = 门禁关闭（`/admin` 提示未启用） |
| `ADMIN_TOKEN` | 否 | 空 | 旧版兼容字段 |

cookie 只保存 `HMAC(NEXTAUTH_SECRET, 账号\n密码)` 摘要，**凭据不落库、不落 cookie**；改密码会让已登录会话立即失效，这是预期行为。

### 4.7 地图瓦片

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `NEXT_PUBLIC_MAP_TILE_URL` | 否 | 高德路网 | 留空 = 不挂瓦片层，用内置 CSS 星场（离线演示最稳） |
| `NEXT_PUBLIC_MAP_TILE_CRS` | 否 | `gcj02` | `gcj02`（高德/腾讯）/ `wgs84`（OSM/CARTO/自建）。留空按域名自动判断 |
| `NEXT_PUBLIC_MAP_TILE_TONE` | 否 | `dark` | `dark` 把浅色瓦片反色压暗成夜视底；`none` 原色铺（卫星影像用这个） |

> 换瓦片源要注意：CARTO 现在需要 API Key，无 Key 会返回 200 + 一张「API KEY REQUIRED」水印图，前端收不到 `tileerror`，降级逻辑不会触发。

## 五、三种 AI 运行模式

| 模式 | 配置 | 适用场景 |
|---|---|---|
| **零密钥**（默认） | `AI_PROVIDER=mock` | 首次跑通、离线演示、CI。识别/分级/检索走确定性规则，结果稳定可复现 |
| **云端多模态** | `AI_PROVIDER=glm` + `AI_API_KEY` + `AI_MODEL=glm-4.6v-flash` | 真实识别与评估效果。建议配降级链 `AI_FALLBACK_MODELS=glm-4.5-flash,glm-4.5v` |
| **私有 / 兼容网关** | `AI_PROVIDER=openai` + `AI_BASE_URL=<你的端点>/v1` | 内网部署或走代理。只要兼容 OpenAI Chat Completions 协议即可 |

切换后建议跑一遍验证：

```bash
npm run ai:selftest        # 直连 Provider，验证密钥与结构化输出
npm run identify:selftest  # 识别管线（可用 --http 走真实接口）
```

## 六、初始化与验收

```bash
npm run db:migrate     # 按 prisma/migrations 建表（推荐）
npm run db:seed        # 幂等：连跑两次数据不会翻倍
npm run db:selftest    # 断言中心点落在点位包围盒内、到每个点位 ≤2km
```

`db:push` 用于快速试验（不生成迁移文件），正式环境一律用 `db:migrate`。

全部自测（合计 400+ 条断言，脚本在 `scripts/`，多数支持 `--http` 走真实接口）：

```bash
npm run db:selftest && npm run ai:selftest && npm run id:selftest
npm run health:selftest && npm run rag:selftest && npm run obs:selftest
npm run alerts:selftest && npm run agent:selftest && npm run insight:selftest
```

## 七、生产构建与部署

```bash
npm ci                                  # 严格按 package-lock 安装
npx prisma migrate deploy               # 生产用 deploy，不生成新迁移
npm run rag:ingest                      # 知识库入库（首次或知识有更新时）
npm run build                           # 含 prisma generate
npm run start                           # 默认 3000 端口
```

单机部署的最小拓扑：

```
用户浏览器 ──HTTPS──> Nginx（TLS 终结 / 反代 / 请求体大小限制 10MB）
                        └──> Next.js (node :3000，PM2 或 systemd 托管)
                               ├──> PostgreSQL 16 + pgvector（容器，5433）
                               ├──> public/uploads（本地磁盘，需持久化）
                               └──> AI Provider（HTTPS，云端 API）
```

几个必须项：

1. **上传目录要持久化**，并与数据库**成对备份**（只备份库会丢图，只备份图会丢关联）。
2. **`AI_PUBLIC_BASE_URL` 改公网地址**，否则视觉模型拉不到图。
3. **Nginx 关缓冲**：SSE 接口（`/api/agent/stream`）需要 `proxy_buffering off;`，响应头已带 `X-Accel-Buffering: no`，但部分反代会忽略。
4. **不要提交 `.env`**：`.gitignore` 已排除；生产密钥走环境变量或密钥管理，不进仓库。
5. **换 Embedding 模型后必须 `npm run ai:reembed`**，否则检索结果不可用。

## 八、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `type "vector" does not exist` | 数据库没装 pgvector | 用 `pgvector/pgvector:pg16` 镜像，或在本机库执行 `CREATE EXTENSION vector` |
| 连上了库但表是空的、数据不对劲 | 本机 5432 上另有一个同名库，Prisma 连错了 | 确认 `DATABASE_URL` 端口为 **5433**（Docker 方案），或核对库名 |
| 识别一直返回「认不出来」 | ① 视觉模型拉不到图（`AI_PUBLIC_BASE_URL` 是 localhost 而服务已部署）② 模型没有视觉能力 | 改成公网地址；确认 `AI_VISION_MODEL` 是视觉模型 |
| 高峰期大量 429 / 1305 | 免费档限流 | 配 `AI_FALLBACK_MODELS` 降级链，或换付费档 |
| 星点整体偏到几百米外 | 坐标口径混用（GCJ-02 写进了库） | 库内统一 WGS-84，只有渲染前 `toTileLatLng()` 转 GCJ-02 |
| 定位按钮点了没反应 | 非 HTTPS / 非 localhost，浏览器禁用 Geolocation | 用 `localhost` 开发；线上配 HTTPS（手机调试可用 `adb reverse`） |
| 地图一片空白但不是报错 | 瓦片源要 Key，返回了水印图 | 换回默认高德瓦片，或把 `NEXT_PUBLIC_MAP_TILE_URL` 留空用内置星场 |
| `/admin` 提示「未启用」 | `ADMIN_PASSWORD` 与 `ADMIN_TOKEN` 都为空 | 在 `.env` 配一个真实口令后重启 |
| 改了 `.env` 没生效 | Next.js 只在启动时读取环境变量 | 重启 `npm run dev` / `pm2 restart` |

## 九、安全约定

- `.env` 已在 `.gitignore` 中，仓库只提交 `.env.example`（占位值，无真实密钥）。
- 生产环境三件套必须替换：`NEXTAUTH_SECRET`、`ADMIN_PASSWORD`、AI 厂商密钥。
- 所有 AI 入口（识别 / 评估 / 问答 / Agent）共用同一套限流与内容安全检查，新增入口不允许绕过（见 `src/lib/safety/`）。
- 匿名提交的记录一律标记 `pendingReview`，未核实前不进入问答引用。
