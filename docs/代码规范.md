# 代码规范

本文是项目实际执行的约定，不是理想清单。每条规则都能在代码或配置文件里找到对应实现；能交给工具强制的，就交给工具。

## 二、分层：接口薄，业务厚

这是本项目最重要的一条结构约定。

```
src/app/api/**/route.ts     只做四件事：解析 → 限流 → 鉴权 → 统一信封
src/lib/**                  业务裁决与落库，不 import next/server，可脱离 HTTP 单测
src/components/**           展示与交互，不直接写 fetch（除极少客户端轮询）
```

`src/app/api/observations/route.ts` 是标准形态：

```ts
export async function POST(req: Request) {
  const ip = clientIpFrom(req.headers);
  const verdict = rateLimit(`obs:${ip}`, RATE_LIMIT.observation);
  if (!verdict.ok) return fail('RATE_LIMITED', '操作过于频繁，请稍后再试');

  const body = await parseBody(req, ObservationFormSchema);
  if (!body.ok) return body.response;

  const result = await createObservation({ ...body.data, ip });
  if (!result.ok) return fail(result.code, result.message);
  return ok(result.data);
}
```

判断标准很简单：**如果一段逻辑没法在 `route.ts` 之外被复用或被测试，它就不该写在 `route.ts` 里**。同一条业务规则（例如「观察记录与预警必须同事务」）只有一个实现，手动提交与 Agent 调用走的是同一个函数，没有旁路。

## 四、类型与契约

所有跨层数据都有 Zod schema，放在 `src/lib/api/*-contract.ts`：

- **接口层**用它校验入参（`parseBody`），**前端**用同一份推导出的类型，不各写一套 interface。
- 响应统一走 `ok()` / `fail()` 信封，错误码是有限枚举（`ErrCode`），前端按码分支而不是匹配文案。
- 对外 DTO 与数据库模型分离：Prisma 实体不直接返回给前端，映射在 `VM`（如 `StarPinAnimalVM`）里完成，避免把 `password` 这类字段漏出去。

## 五、注释：写「为什么」，不写「是什么」

文件头必须回答三件事：这个文件解决什么问题、为什么这么设计、有哪些反直觉的约束。`src/lib/animals/location.ts` 的头注释是模板：

```ts
/**
 * 「在哪看到它」—— 一次目击地点落到两条数据上：观察记录 + 档案点位。
 *
 * 为什么需要这一层（2026-10-29）：
 *   星图上的点来自 `Animal.mapLat/mapLng`，而观察记录虽然也有两列坐标，
 *   但前端记录页从来没有定位入口 —— 结果是「星图上的点位」只能靠管理员手动补。
 *
 * 铁律：**坐标不由模型给**。
 *   让 LLM 直接输出 lat/lng，它会给一个看起来很像的地址（甚至别的城市）。
 */
```

约定细节：

- **决策标日期**：`（2026-10-29 补一条例外：设备定位可以给坐标）`——后来的人能判断这条约束是何时、因为什么加的。
- **踩过的坑写进注释**：例如「补 `animalCode` 之前，用户说 No.001 受伤了却被建成新档案」，注释本身就是回归测试的说明。
- **不写复述代码的注释**：`// 遍历数组`、`// 返回结果` 一律删掉。
- **不用 TODO 空话**：要么写清「待办 + 触发条件」，要么开 issue，不留 `// TODO: 优化`。

## 六、视觉令牌：禁止硬编码颜色

颜色只能来自 `src/styles/tokens.css` 与 `src/lib/semantic.ts`。ESLint 强制：

```json
{
  "selector": "JSXAttribute > Literal[value=/^#(5BE49B|FFD166|...)$/i]",
  "message": "语义色必须走设计令牌（text-star-green / bg-space-800 / CSS 变量），禁止在 JSX 属性里硬编码十六进制。"
}
```

允许例外的地方只有三处，在 `overrides` 里显式关掉：`src/lib/constants.ts`、`src/lib/semantic.ts`、`src/styles/*`。

理由：健康等级三档（绿/黄/红）散落在十几个组件里，一旦硬编码，改主题就会漏改。语义映射集中一处，改一次全站生效。

## 七、错误处理

- 业务函数返回 `{ ok: true, data } | { ok: false, code, message }`，**不抛异常**；异常只留给真正的程序错误。
- 面向用户的 `message` 必须给出下一步怎么办。反例：`位置无效`；正例：`只认得这些校园角落的坐标：图书馆、李园食堂……请用其中一个名字再说一次`（`unknownSpotMessage()`）。
- 降级不静默：任何 fallback 都要在响应里留标记（`degraded` / `notice`），并在 UI 上显示。用户以为事情办成了，比明确失败更糟。
- 不影响主流程的副作用失败只记日志，不改主结果（例如记录已落库但挪点位失败，`log.warn` 后照常返回成功）。

## 八、Git 提交规范

采用 Conventional Commits，中文描述，一条提交做一件事：

```
<type>(<scope>): <描述>

type: feat | fix | refactor | docs | test | chore | perf | style
scope: identify | health | agent | rag | alerts | map | admin | ui | db | docs
```

格式示例（评审时仓库里的真实提交请以 `git log` 为准）：

```
feat(agent): recordLocation 支持 useCurrentPosition，坐标由服务端从授权里取
fix(identify): 置信度不足时不再返回空候选，改为强制 candidate 档
docs(env): 补 AI_ATTEMPT_TIMEOUT_MS 与降级链的说明
refactor(map): 抽出 movePinToSighting，记录页与 Agent 共用一份审计字段
```

要求：

- 标题 ≤ 50 字，说明「做了什么」；正文写「为什么」，尤其是修复类提交要写清触发条件。
- 一个提交只解决一件事，不把格式化与逻辑改动混在一起（评审看 diff 时才能读懂）。
- 不提交 `node_modules/`、`.next/`、`.env`、`*.tsbuildinfo`、上传的图片（已由 `.gitignore` 覆盖）。

## 九、自测组织

- 每个核心模块有对应脚本：`scripts/<module>-selftest.ts`，多数支持 `--http` 走真实接口，验证的是「契约」而不只是「函数」。
- 断言优先测**边界与失败路径**：参数被拒、置信度不足、越界坐标、重复提交——正常路径反而最容易通过。
- 修 bug 时先补一条会失败的断言，再改实现（`scripts/agent-selftest.ts` 里的 `[7]` 就是这样来的）。
